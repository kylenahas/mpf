# MPF docs site (Hugo)

End-user-first documentation for MPF: people writing machine config files come first, developer material second.
Everything is derived from this repository's source and the configs in `mpf/tests/machine_files/`.

## Layout

```text
docs-site/
  hugo.toml
  content/              hand-written pages (get-started/, build/, architecture/)
  content/reference/    GENERATED by tools/gen_reference.py (git-ignored; do not edit)
  layouts/              theme: baseof/single/list/index, sidebar, breadcrumbs, search index, shortcodes
  assets/               css/site.css, js/site.js (search, theme toggle, copy buttons; minified + fingerprinted)
  tools/gen_reference.py  source -> reference pages
  tools/check_docs.py     YAML snippet + config key + internal link checks (static)
  verify/test_guides.py   runs each guide's complete config on MPF (read from the page) and checks the described behavior
```

## Build

From the repository root. The repo's `venv/` (git-ignored) has the local MPF installed editable; create it once with
`python -m venv venv` and `venv\Scripts\python -m pip install -e .`.

```bash
venv/Scripts/python -I docs-site/tools/gen_reference.py . docs-site/content
venv/Scripts/python -I docs-site/tools/check_docs.py . docs-site/content
venv/Scripts/python -I -m unittest discover -s docs-site/verify
hugo server -s docs-site
```

Shortcodes for pages: `{{< note >}}`, `{{< warn >}}`, `{{< tip >}}`. Front matter `verified: "..."` and
`unverified: "..."` show a status pill under the title.

## Rules

- Every claim comes from the code or a test config; cite file paths.
- Config snippets come from `mpf/tests/machine_files/**` or are run on MPF before publishing. Mark anything not run
  with `unverified:` front matter or a `warn` callout.
- `check_docs.py` must pass.
- A page with `verified:` front matter has a test class in `verify/test_guides.py` that reads its config from the
  page. Change the page, rerun the tests.

Findings from running MPF (already reflected in the pages):
- On virtual platforms the trough starts empty unless `virtual_platform_start_active_switches` lists its switches.
- `-x` (virtual) does not move balls; `-X` (smart virtual) does. Use `-X` for a playable test machine.
- With no playfield switch, a ball counts as on the playfield after the 10 s default eject timeout.
- `game` mode is always loaded: `mpfconfig.yaml` has `modes: [attract, game]` and user lists are added to it.
- `switch_player:` can press switches on a schedule; useful with no keyboard/monitor.
- Switch `<name>_active` and `sw_<tag>` events are only posted when something handles them (or `debug: true`).
- A coil cannot be enabled without `default_hold_power`, `max_hold_power` or `allow_enable`.
- MPF bug: `autofire_coils` `timeout_watch_time` is divided by 1000 twice (`autofire.py` `_initialize` and `_hit`),
  so the stuck-pop-bumper timeout never trips at real hit spacing. Documented with a warn callout;
  `verify/test_guides.py::test_timeout_real_spacing` is an expected failure until fixed.
- `flippers: power_setting_name` scales `mpf: default_pulse_ms` (10 ms), not the coil's `default_pulse_ms`, unless
  `main_coil_overwrite: pulse_ms` is set.
- Ball search is off unless `enable_ball_search: true` (playfield) or `mpf: default_ball_search: true`.
- Only the ball served at ball start is player-controlled; the `playfield.add_ball` docstring still mentions an old
  `player_controlled_eject_tag`, the setting is `player_controlled_eject_event`.
