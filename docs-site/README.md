# MPF docs site (Hugo)

End-user-first documentation for MPF: people writing machine config files come first, developer material second.
Everything is derived from this repository's source and the configs in `mpf/tests/machine_files/`.

## Layout

```text
docs-site/
  hugo.toml
  content/              hand-written pages (get-started/, build/, examples/, architecture/)
  content/reference/    GENERATED by tools/gen_reference.py (git-ignored; do not edit)
  layouts/              theme: baseof/single/list/index, sidebar, breadcrumbs, search index, shortcodes
  assets/               css/site.css, js/site.js (search, theme toggle, copy buttons; minified + fingerprinted)
  tools/gen_reference.py  source -> reference pages
  tools/check_docs.py     YAML snippet + config key + internal link checks (static)
  verify/test_guides.py   runs each guide's complete config on MPF (read from the page) and checks the described behavior
```

## Build

From the repository root. The repo's `venv/` (git-ignored) has the local MPF installed editable; create it once with
`python -m venv venv` and `venv\Scripts\python -m pip install -e .`.

```bash
venv/Scripts/python -I docs-site/tools/gen_reference.py . docs-site/content
venv/Scripts/python -I docs-site/tools/check_docs.py . docs-site/content
venv/Scripts/python -I -m unittest discover -s docs-site/verify
hugo server -s docs-site
```

## Publishing (GitHub Pages)

`.github/workflows/docs-pages.yml` builds and deploys the site on every push to the `docs-site` branch that touches
`docs-site/`, `mpf/` or the workflow (or by hand from the Actions tab). It installs MPF, generates the reference,
runs `check_docs.py`, builds with Hugo 0.169.0 and publishes to `https://<owner>.github.io/<repo>/`.

The site works from a subfolder: layouts use `relURL`/`RelPermalink`, and `layouts/_default/_markup/render-link.html`
prefixes root-relative Markdown links (`[x](/build/modes/)`) with the base path. Check a subfolder build locally with
`hugo server -s docs-site --baseURL http://localhost:1320/mpf/ --port 1320 --appendPort=false`.

One-time repository setup: Settings > Pages > Source: GitHub Actions; allow `docs-site` in Settings > Environments >
github-pages > deployment branches; on a fork, enable workflows in the Actions tab.

Shortcodes for pages: `{{< note >}}`, `{{< warn >}}`, `{{< tip >}}`. Front matter `verified: "..."` and
`unverified: "..."` show a status pill under the title.

## Rules

- Every claim comes from the code or a test config; cite file paths.
- Config snippets come from `mpf/tests/machine_files/**` or are run on MPF before publishing. Mark anything not run
  with `unverified:` front matter or a `warn` callout.
- `check_docs.py` must pass.
- A page with `verified:` front matter has a test class in `verify/test_guides.py` that reads its config from the
  page. Change the page, rerun the tests. For multi-file machines, put a line holding only the file path
  (`` `modes/base/config/base.yaml`: ``) before each block; `page_files()` picks those up, and a block labelled
  `config/config.yaml` is the machine config.

Findings from running MPF (already reflected in the pages):
- On virtual platforms the trough starts empty unless `virtual_platform_start_active_switches` lists its switches.
- `-x` (virtual) does not move balls; `-X` (smart virtual) does. Use `-X` for a playable test machine.
- With no playfield switch, a ball counts as on the playfield after the 10 s default eject timeout.
- `game` mode is always loaded: `mpfconfig.yaml` has `modes: [attract, game]` and user lists are added to it.
- `switch_player:` can press switches on a schedule; useful with no keyboard/monitor.
- Switch `<name>_active` and `sw_<tag>` events are only posted when something handles them (or `debug: true`).
- A coil cannot be enabled without `default_hold_power`, `max_hold_power` or `allow_enable`.
- MPF bug: `autofire_coils` `timeout_watch_time` is divided by 1000 twice (`autofire.py` `_initialize` and `_hit`),
  so the stuck-pop-bumper timeout never trips at real hit spacing. Documented with a warn callout;
  `verify/test_guides.py::test_timeout_real_spacing` is an expected failure until fixed.
- `flippers: power_setting_name` scales `mpf: default_pulse_ms` (10 ms), not the coil's `default_pulse_ms`, unless
  `main_coil_overwrite: pulse_ms` is set.
- Conditions are only checked when first evaluated: `{true}` (lower case) boots fine and stops MPF at the first
  matching event. A `current_player` condition outside a game is false, not an error.
- A condition reads device state from before the event is handled: `s_ramp_active{device.counters.x.value==2}` is
  true on the third hit. Use `logicblock_<name>_hit{count==2}` instead.
- `events_when_complete` / `events_when_hit` replace the default `logicblock_<name>_complete` / `_hit` events.
- `mpfconfig.yaml` defines `combo_switches: both_flippers` (tags `left_flipper` + `right_flipper` -> `flipper_cancel`)
  and `timed_switches: flipper_cradle`; user entries with those names are merged into them.
- A shot group posts `<group>_complete` / `<group>_unlit_complete` at every ball start (all members unlit); rules
  should use `<group>_lit_complete`. Shot states are player variables (`shot_<name>`) and survive the ball.
- `show_player` `loops` defaults to -1 (repeat forever); `loops: N` plays N+1 times. `verify/test_guides.py` has
  `start_ball_now()` for sampling show timing without `start_game()`'s 1 s advance.
- Event queue is depth-first: events posted by handlers run before already-queued events. Queue-event handlers run
  one after another, so a `wait()` also delays lower-priority handlers of the same event.
- Ball end order is `ball_drain`, `ball_will_end` (ball modes stop), `ball_ending`: ball-length modes never see
  `ball_ending`. A mode player keyed to the mode's own start event errors when the mode first starts.
- Machine-config players register at priority 0, machine `*_events` at 1, mode players at the mode priority.
- Errors that pass startup and fail at first use: missing `default_source_device` (game start), lower-case
  `true` in a condition, a mode player on its own start event, single-wound flipper without hold power.
- `mpf game -t` turns the text UI off despite its help text. Error messages link to missionpinball.org/latest/logs.
- MPF bug: `multiball_(name)_lost_ball` is documented in the source but `multiball_(name)_ball_lost` is posted.
  `gen_reference.py` `EVENT_CORRECTIONS` adds a warning to the events page and the multiballs page;
  `TestEventCorrectionsStillHold` fails once MPF is fixed, so the correction can be removed.
- A multiball lock's count is per player and survives the multiball; without `reset_count_for_current_player_events`
  the lock stays full for the rest of the game.
- `playfield_active` is only posted when a switch is hit while the playfield count is 0; if the eject timeout confirms
  the ball first it never comes. A ball save with `timer_start_events: playfield_active` then never times out. Use
  the feeding device's `balldevice_<name>_ball_eject_success`.
- MPF bug: `extra_balls: max_per_game` (default 1) only counts that entry's own `award_events`; light-and-collect via
  the group is unlimited unless the group has `max_per_game` (the `ExtraBall.light` docstring says lighting counts).
- MPF bug: `ExtraBallGroup.award` sets player var `extra_ball_group_{}_num_lit` (missing `.format`), posting
  `player_extra_ball_group_{}_num_lit`.
- Ball search is off unless `enable_ball_search: true` (playfield) or `mpf: default_ball_search: true`.
- Only the ball served at ball start is player-controlled; the `playfield.add_ball` docstring still mentions an old
  `player_controlled_eject_tag`, the setting is `player_controlled_eject_event`.
